## What it is

A working evaluation task, written against a real eval harness — UK AISI's
Inspect or METR's tooling — published where a stranger can read the code and
run it. Constellation/Astra's published technical-track guidance names this
directly: "build an eval task using an open-source AI safety tool (such as
METR's tools or UK AISI Inspect) and publish it." The artifact is the eval
plus the writeup of what it found.

## What strong looks like

- The threat model is stated in one paragraph at the top, before any code:
  what behaviour would be dangerous, in what deployment, and why measuring it
  now matters.
- There is a **control condition**. If you measure a model doing X under
  pressure, you also measure it without the pressure. A single-arm number is
  not a measurement.
- There is a stated **falsifier**: the result you would have accepted as
  "this eval found nothing." Written before you ran it, not after.
- The scorer is specified and its failure modes are named. If a model judges,
  you report judge-vs-human agreement on a sample, not just the aggregate.
- You report **where it fails**: prompts the eval mis-scores, populations it
  doesn't generalise to, the ceiling effect you hit at the frontier model.
- Sample size and variance are reported. Seeds are fixed and stated.
- It runs from a clean checkout with documented setup and a small sample
  budget, so a reviewer can reproduce a partial result in under ten minutes.
- The dataset is versioned and in the repo (or generated by a script in the
  repo), not a CSV that lives on your laptop.

## What weak looks like

- A prompt set with a regex scorer and no control arm — "the model complied
  47% of the time" against nothing.
- Wrapping an existing benchmark in Inspect and reporting the number the
  benchmark already publishes. That demonstrates you can install a package.
- Threat model written after the results, reverse-engineered to fit what you
  found.
- A model-graded scorer with no agreement check, where the interesting result
  is actually a judge artifact.
- n=20, one seed, differences of a few points reported as findings.
- "Results coming soon" in the README. An eval nobody has run is not evidence.
- A repo of your own scaffolding that reimplements what Inspect already does.
  The tool choice is part of the signal — using the field's shared harness is
  the point.

## How to produce it

1. Pick a behaviour you can define adversarially in one sentence. Narrow beats
   important: a sharp result on a small question outranks a vague result on a
   large one.
2. Write the threat model paragraph and the falsifier **first**, in the README,
   and commit that before you write task code.
3. Work the bench's eval-design problems — `e01` (paired eval / position
   debias), `e02` (judge agreement, Cohen's kappa), `e03` (format robustness
   gap). They are small implementations of the three mistakes that most often
   sink a first eval.
4. Build the task in Inspect. Keep the dataset in-repo and generated by script.
5. Run a pilot at small n against a cheap model. Look for the eval passing when
   it should fail — a broken eval usually looks clean.
6. Add the control arm and re-run. If the gap between arms is inside your
   variance, say so; that is a publishable negative result.
7. Write the "where this fails" section honestly, then publish: repo, README,
   and a short post. Post it to the Alignment Forum or LessWrong and link the
   repo.

## How a selector sees it

They open the repo, read the first screen of the README, and look for a threat
model and a control condition. If both are there they skim the results table
and the limitations section — total time maybe two minutes. What makes it
skippable: no README structure, no stated comparison, or a results section
that reads as uniformly positive. Reviewers have seen many evals that measure
prompt sensitivity and call it a safety property; the limitations section is
what separates you from that pile. None of this guarantees anything —
selection is capacity-bound and strong artifacts get rejected — but this is
the artifact that gets read rather than skimmed.
